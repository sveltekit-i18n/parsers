# 3.0.0
Initial release. `@sveltekit-i18n/parser-fluent` brings [Fluent](https://projectfluent.org), Mozilla's localization system, to [`@sveltekit-i18n/base`](https://github.com/sveltekit-i18n/base) v3:
* Every message is a Fluent pattern, the text after `key =` in an `.ftl` file, formatted by [`@fluent/bundle`](https://github.com/projectfluent/fluent.js/tree/main/fluent-bundle), the package's only runtime dependency: variables, `NUMBER()` and `DATETIME()`, selection on plural categories, exact numbers and strings, and terms. Base's parser contract checks (the repository's `contract/` set) run beside the package's own tests.
* `parser(options)` takes Fluent's own options (`useIsolating`, `functions`, `transform`), `onReport`, `terms` and `cacheLimit`, and returns the parser the base library expects; `parse(value, [payload], locale, key)` maps the library's `t(key, payload?)` onto a pattern formatted for that locale. `terms` holds Fluent source per locale, whose terms - with their variants and attributes - every message of that locale can reference; the messages such a source holds are left out. A message cannot reference another message, nor hold attributes: an attribute is a key of its own.
* `FluentNumber`, `FluentDateTime`, `FluentNone` and `FluentType` are re-exported, with the `FluentFunction`, `FluentValue` and `FluentVariable` types, from the copy of `@fluent/bundle` the parser formats with. A payload carries a `FluentNumber` or a `FluentDateTime` to set what a message cannot - a currency, an ordinal plural, a time zone - and a custom function returns one.
* The parser fails soft. A message that cannot be compiled whole, or that nothing of could be formatted, is returned raw and reported as `failed-message`; a placeable that cannot be resolved renders as Fluent's fallback for it (`{$name}`) while the rest of the message renders, reported as `fallback-value`. A key naming no message yields the empty string: what a missing translation renders as is [`fallbackValue`](https://github.com/sveltekit-i18n/base/blob/master/docs/README.md#fallbackvalue), which base answers before this parser is called.
* `onReport` is required, `null` included: the parser writes to no channel of its own, so where a report goes is stated by whoever builds the parser. A report carries `code`, the `key` and `locale` of the call, a one-sentence `message`, and the `error` Fluent threw or handed back where there was one; a report channel that throws is contained like any other failure.
* `cacheLimit` sets how many compiled messages a parser keeps, one count across every locale, the least recently used making room: 10,000 by default, `0` compiles on every call, `Infinity` never evicts, and a value that is no count keeps the default. A parser also keeps one bundle per locale, up to 1,000 locales, which holds that locale's terms and `Intl` formatters and goes with them when it is evicted.
* `extractParamsFactory` reads the parameters a message names, as a named export beside the default one, from the syntax tree `@fluent/bundle` compiles. Each parameter says the payload key it is named by, its kind, the keys a selector names explicitly, and the variants it lives under. The kind is `string` where a select expression compares the parameter with string keys, none a plural category but `other` and one of them neither the default's nor `other`; anything else is `unknown`, since a number or a date may be a `FluentNumber` or a `FluentDateTime`. It is the build-time half of the base parser contract, which is why it is a named export rather than a member of the parser object: a message scanner is of no use while rendering, and the package declares `sideEffects: false` so a bundle that never reaches it drops it.
* `Config` and `Parser` are the exported types.
* ESM only; requires Node.js 22.12, Bun 1.2 or Deno 2, or newer; `@sveltekit-i18n/base` v3 is a peer dependency.
